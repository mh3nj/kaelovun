The principle

Processing should never become an excuse for data loss.

Kaelovun treats a creative project as a package, not a single document. It looks at the whole thing before deciding what should happen to each part.

01 / PRESERVATION
Keep the things that matter, even when Kaelovun cannot transform them.

Licenses, documentation, fonts, references, images, unknown files, and other preservable content stay in the package. Originals are not edited in place.

Conservative classification
Original directory hierarchy retained
Unknown files are preserved
02 / INPUT

One file. A whole folder. An archive. Same idea.

There is no need to choose a processing method first. Kaelovun scans the input, classifies what it finds, and routes each part through the appropriate processor.

Files and directories
ZIP, RAR, 7z and tar archives
Nested archives with depth limits
03 / SAFETY

The original stays untouched.

Kaelovun copies inputs into an isolated workspace before processing. Cleanup only happens after archive integrity and manifest verification succeed.

04 / PACKAGING

A finished package, not a loose collection of files.

The original logical structure is reconstructed, previews are generated for transformable creative assets, and the result is stored as a verified solid RAR5 archive.

The pipeline

From messy input to a verified package.

Every package follows the same disciplined path. The details change with the files inside it, but the safety model stays the same.

01DiscoverScan and classify the input.
02Extract / CopyMove content into an isolated workspace.
03ClassifyTransform, preserve, container, or license.
04PreviewCreate preview and thumbnail outputs.
05ProcessHandle supported creative documents.
06ReconstructRestore the package structure.
07ArchiveCreate a solid RAR5 package.
08VerifyCheck integrity and the expected manifest.
09CleanupOnly after verification succeeds.

Kaelovun produces standard files that can be used by a file manager, search tool, asset system, or another application. Evoury can consume that output as a DAM, but the processing engine remains useful on its own.

Questions

The short version.

A few practical answers about what Kaelovun is, what it does, and where it fits.

What can I give Kaelovun?

A single file, a directory, or an archive. Archive formats include ZIP, RAR, 7z, tar, tar.gz, tar.bz2 and tar.xz.

Does it preserve licenses and files it does not understand?

Yes. The preservation model keeps licenses, documentation, fonts, images, unknown files and other content that is not meant to be transformed.

Does Kaelovun modify my originals?

No. Inputs are copied into an isolated workspace before processing. The originals stay where they are.

Can I automate it?

Yes. Kaelovun has a headless CLI as well as the interactive GUI, including resume support for interrupted jobs.

Is Kaelovun tied to Evoury?

No. Kaelovun is a standalone application. Evoury can use its output, but Kaelovun can be used without Evoury.

Can I choose preview and thumbnail formats separately?

Yes. The main preview and thumbnail have separate format, dimension and quality controls.

Can I choose automatic or manual naming?

Yes. Automatic naming can use the source name, while manual naming lets you choose the package name yourself. This is useful when preparing mockups, presentations, or curated deliveries.
